# StockTake test report: Claude Code session, 2026-10-30

- Source: Claude Code session (Black Canyon Software, Can-AI project)
- Date: 2026-10-30
- StockTake version / commit tested: `ff7d6c0` (`git rev-parse --short HEAD`), tool prints `stocktake 0.1.0`
- Platforms: Windows 10 Pro + Python 3.11.9; WSL2 Ubuntu (KPrime, kernel 6.6) + Python 3.12.3
- Ecosystems exercised: python (requirements, constraints, pyproject incl. optional + dependency-groups, Pipfile, Pipfile.lock, poetry.lock, uv.lock, pdm.lock, Dockerfile pip), npm (package.json, package-lock v1 and v3, node_modules), workflows (tag, moving tag, SHA + comment), binaries (Dockerfile release downloads); unread kinds (go.mod, Cargo.toml, yarn.lock, environment.yml) checked only for the "unread" notice
- Verdict: A careful, honest and fast-enough checker whose findings I could not fault where it reads a file (zero false positives, exact agreement with OSV and `npm audit`), but it is not yet safe to rely on unattended because it silently skips some files it cannot read, has no real offline mode, and its one-line summary can say "nothing unsafe" when it checked nothing.

## 1 Summary

**Good**
- Accuracy where it reads: across about 30 example projects and one 665-dependency project, 0 false positives. The vulnerable set equalled a direct OSV batch query exactly (4 of 655 distinct package versions) and equalled `npm audit`'s advisory-bearing packages exactly.
- Honest about what it does not know: offline gives `unknown` + exit 2 (never clean), unread manifests are named, a missing Python environment produces a note that names the fix flag.
- Output is plain ASCII, no ANSI colour when piped, JSON/SARIF/summary are byte-identical on a second run, SARIF validates against the official 2.1.0 schema (5 of 5 documents checked), Windows and Linux give identical findings on all 22 generated projects.
- Install works as documented once the interpreter name is fixed; zero runtime dependencies; the pytest plugin, `init`, `vendor` and policy/hold/exclude all behaved as documented.
- The privacy claim is true: with a logging proxy the only hosts contacted were `pypi.org`, `registry.npmjs.org`, `api.github.com`, `api.osv.dev`.

**Blocks adoption (for an unattended or AI-sandbox user such as Can-AI)**
1. No offline or pinned-advisory mode (only the 6-hour cache, with no stale fallback, and a pytest-only `STOCKTAKE_OFFLINE`).
2. Silent skips: a truncated `package.json`, an unreadable file, a UTF-16 `requirements.txt` and a binary file all give "nothing found to check", exit 0. A malformed `pyproject.toml` correctly gives exit 2, so the behaviour is inconsistent.
3. It scans git-ignored third-party folders: on Can-AI it reported 129 dependencies instead of 41 (88 extra, 57 of them "unpinned" noise).
4. The summary line (`--format summary`) says `nothing unsafe, 0 outdated (300 checked)` for 300 packages that do not exist on the registry, and for 5 unpinned ones. Exit code is 0 in both cases.
5. The 60-82 MB single-file cache (full PyPI JSON per package) is loaded and rewritten each run: about 330-470 MB resident on KPrime for a 40-package project.

**Top five changes by value**
1. Add `--offline` / `--cache-only` and a documented snapshot-database option, allow stale cache use, and shrink the cache to the fields actually used.
2. Make skipping loud: a notice (and exit 2 under a `--strict` flag) for every file that matched a manifest name but could not be read or parsed; reject unknown config keys; follow `-r`/`-c` includes.
3. Respect `.gitignore` (or add `--tracked-only`) and separate direct from transitive dependencies in the report.
4. Give the JSON a `schema_version`, tool version, root, an explicit `complete` / `exit_code`, relative `config_source`, severity-ordered findings, and publish the schema; apply `--only` to JSON as DESIGN.md says.
5. Make the summary line honest (include unpinned/unknown/unread counts), and add `--fail-on unknown,unpinned,unread` as an opt-in.

## 3 Install and first run (friction log)

Windows, literal README steps (clone replaced by the repo path, as instructed):
```
py -3.11 -m venv venv-win                          # OK (py launcher present)
venv-win\Scripts\python -m pip install -e C:\...\StockTake_BCS    # OK, 1 package, no deps, ~5 s
venv-win\Scripts\stocktake --version               # stocktake 0.1.0
```
Also verified the other README route in a clean venv: `pip install git+https://github.com/BlackCanyonSoftware/stocktake_BCS` works in about 20 s and gives `stocktake 0.1.0`. `git ls-remote` shows the GitHub repo is public and its HEAD is `ff7d6c0`, the same commit as the local repo.

KPrime (Linux), literal README steps:
```
git clone https://github.com/BlackCanyonSoftware/stocktake_BCS.git     # OK, no login needed
python3.11 -m venv .venv          # FAILS: python3.11: command not found (KPrime has only 3.12.3)
python3 -m venv venv-lin          # works; pip -e install works; stocktake 0.1.0
```

Friction list and proposed README corrections:
1. **Linux command names a Python that may not exist.** `python3.11 -m venv` fails on a stock Ubuntu 24.04 with 3.12. Say "any Python 3.11 or newer, e.g. `python3 -m venv .venv`", and mention that Debian/Ubuntu may need the `python3-venv` package (it was already installed here, so unverified).
2. **"Not published" vs a public repo.** The README says it is not published but the clone URL works anonymously. Say "not on PyPI; the source is public at ...".
3. **The install block creates `.venv` inside the clone.** A stranger who only wants the command should create the environment elsewhere; and the README's own table ("Needs StockTake installed? yes, anywhere") never says which environment the project's pytest will see. One sentence needed.
4. **`--help` and README disagree on hosts.** Help lists `pypi.org, api.github.com, api.osv.dev`; README (and behaviour) also include `registry.npmjs.org`.
5. **`--environment PATH` relative paths are resolved against `--root`, not the current directory** (I got "no Python environment found at ...\ex\e10-ranges-env\venv-small"). Not mentioned anywhere.
6. **The CI snippet's `|| true` also swallows exit 2** (registries unreachable, bad config), so a broken run uploads an empty SARIF and goes green. Suggest `|| [ $? -eq 1 ]`. (From reading shell semantics; I did not run GitHub Actions.)
7. **`stocktake vendor NAME`** with a non-existent directory writes a *file* called `NAME` (help does say "or the file to write", but it is a trap). No error.
8. First-run surprise: the default cache is created at 60-80 MB, which is not mentioned in the Privacy section.
9. The pytest plugin cannot be imported without pytest (expected, but "complete tool" in the README sentence suggests otherwise for someone checking with `import`).

## 6 Output formats and exit codes

Exit codes as documented, all observed: 0 (clean or only outdated/unpinned/unknown/unread), 1 (vulnerable, yanked, expired or malformed policy), 2 (offline, bad TOML, unknown ecosystem, `--config` missing, `--root` not a directory). A policy entry with no reason is exit 1, not 2.

- **Text**: no ANSI codes found in any piped output (grep count 0). Header, sections and "..and N more (command)" lines are clear. Rows are ordered by file name; a low-severity package (deepmerge) is listed before a high one (serialize-javascript) within VULNERABLE, so "worst first" holds only between sections.
- **JSON** (keys: `date, offline, failed, counts, notes, config_source, policy_problems, unread_manifests, accepted_unread, findings`). Stable: byte-identical on repeat and across `--refresh`. Problems for programs: no `schema_version`, no tool version, no root, `date` only (no time); `config_source` is an absolute local path; `failed` is `false` when offline (exit 2); the offline reason is the raw Python text `offline: <urlopen error Tunnel connection failed: 502 Bad Gateway>`; errors (bad config) print to stderr and nothing to stdout, so `--format json | jq` gets empty input; `--only` does not narrow JSON.
- **SARIF**: valid; `error`/`note` levels; offline run gives `executionSuccessful: false` with an error notification and still emits the 4 results as notes. Fingerprints duplicate when the same package appears twice in one file (pyproject groups).
- **Summary**: `stocktake: 3 vulnerable (4 checked)` / `stocktake: could not check (offline: ...)` / `stocktake: nothing found to check`. It omits unpinned, unknown, unread and policy counts except overdue policy.
- Every format reached the same findings on Windows and Linux; only error messages differ in path separators.

## 10 Suggestions for the product (prioritised)

**P0 (blocks use)**
1. Silent skips. Evidence: e08c, e08k, e14, e08f all gave exit 0 "nothing found". Report every file that matches a manifest name but could not be read or parsed (notice in text, `skipped` list in JSON, exit 2 with a `--strict` flag); decode UTF-16/BOM files.
2. Summary and exit code can reassure falsely. Evidence: 300 nonexistent names -> `nothing unsafe, 0 outdated (300 checked)`, exit 0; 5 unpinned likewise. Include `N unpinned, N unknown, N unread` in the summary, and add `--fail-on unknown|unpinned|unread`.
3. Real offline mode (see section 11). Evidence: no CLI flag exists; only cache; `STOCKTAKE_OFFLINE` affects only pytest.

**P1**
4. Honour `.gitignore` / `--tracked-only`; evidence: Can-AI 129 vs 41 findings.
5. Validate config keys (reject unknown), validate `[tool.stocktake]` anywhere it is read. Evidence: `excludes` typo ran with exit 1 and applied nothing.
6. Follow `-r`/`-c` includes regardless of file name. Evidence: e15 idna missed.
7. JSON contract: `schema_version`, tool version, root, `complete`, `exit_code`, relative paths, structured offline reason, severity-ordered, `--only` applied, error object on stdout when `--format json`. Publish the schema file.
8. Order VULNERABLE by highest severity, then name. Add direct/transitive flag to JSON and group transitive majors (e09: 275 outdated).
9. Show suppressed advisories ("2 ignored by policy, until 2027-01-01") in text and JSON.
10. Evaluate yanked before or alongside advisories so `withdrawn` counts are true.
11. Shrink and index the cache (store version list, withdrawn set, latest; not whole documents); target under 5 MB.
12. Prefixed release tags (`jq-1.6`, `release-1.2`) in the binaries reader; report unrecognised release-download URLs as unread rather than silent.

**P2**
13. Line numbers for lock files and pyproject groups; distinct SARIF fingerprints (add group or package index).
14. Walk upward to find the project root (or say "no manifest in this folder; looked at: ..., try --root").
15. Resolve `--environment` relative to the current directory and say so in `--help`.
16. List `registry.npmjs.org` in `--help`; mention the cache size in the README.
17. `vendor` should refuse a non-existent directory name instead of creating a file.
18. Reuse one TLS connection per host (47 CONNECTs for 15 packages).

**Side by side (same inputs, Can-AI repo, read-only)**

| | Can-AI `depcheck` | StockTake 0.1.0 |
|---|---|---|

| With `exclude = ["docker/pentest/pins"]` and the same two hold-back entries | 41 | 40; the only difference is the unpinned `pip` in the excluded Dockerfile; same outdated (hypothesis, websockets), same held (subfinder, llama-swap) |
| Time cold / warm | 5.3 s / n.a. | 8.1 s / 0.7 s |
| Peak memory | 325 MB | 467 MB cold / 326 MB warm |
| Code | one module, 505 lines | 3,461 lines, 4 ecosystems |
| JSON | `date, offline, policy_problems, failed, findings` | superset: adds `counts, notes, config_source, unread_manifests, accepted_unread` (finding fields are identical) |
| Exit codes | 0 / 1 / 2 same meaning | same |
| Policy file | `config/deps-policy.yaml` (id/package, reason, until) | `.stocktake.toml` same semantics; needs conversion |
| Guards | Test fails if the repo gains a manifest the checker cannot read | StockTake lists unread files but exit stays 0 |
| Excludes | hard-coded list in code | config `exclude`; no `.gitignore` awareness |
| Ecosystems | PyPI (Dockerfile pins, pyproject via `.venv`), GitHub releases | those plus npm, lock files, workflows, requirements; no Go/Rust/containers yet |

What Can-AI's checker does that StockTake does not: the unread-manifest guard that fails the test suite; `.gitignore`-consistent scope by hand-tuned excludes; hold-back entries by name with the reason shown in the report row; stability (it is the code Can-AI already trusts). Reverse: more ecosystems, lock files, SARIF/summary/pytest plugin, config validation for known keys, cache of the same size class (Can-AI's cache location differs, `~/.cache/canai-deps`).

**What Can-AI would need before adopting**
- Machine interface: JSON as above plus a `schema_version`, a documented schema file, and exit codes (already the same: 0/1/2). Can-AI's `scripts/canai-deps --format json` is a drop-in subset today, so the migration risk is small.
- Offline / pinned database mode for AI sandboxes with no network: add `--offline` that reads only a snapshot (a dated file produced by an online run on a trusted machine: PyPI version lists, withdrawn sets, OSV results for the pinned versions) and says the age of that snapshot in the header; fail or warn when older than N days. StockTake's cache could become that snapshot once it is small and has a stable format.
- Speed: fine (warm 0.7 s); cold 8 s on a busy KPrime is acceptable for a nightly job.
- Container use: pure Python, no dependencies, so `pip install` in the dev image or the single `stocktake_vendored.py` file would work; I did not run it inside a container. The cache directory needs a volume, or use the snapshot approach.
- Non-technical owner: the text report is readable but written for developers (GHSA ids). A "what to do next" line per finding exists for vulnerable ones ("upgrade to X"); there is no plain-language digest, no HTML/Markdown report and no change-since-last-run diff. For Can-AI this probably means a small wrapper that reads the JSON and writes one paragraph.
- Scheduling: nothing built in; run `stocktake --format json` from the existing systemd timer or the scheduled-task mechanism, store the previous JSON and diff counts. The exit codes already separate "unsafe" from "could not check".
- Proposed integration: (1) keep `scripts/canai-deps` as is; (2) add a nightly `stocktake --format json --config ...` beside it for 30 days and compare; (3) set `exclude` for `docker/pentest/pins` (git-ignored third-party clones) and port the two hold-back entries; (4) keep Can-AI's unread-manifest guard test, reading `unread_manifests` from StockTake's JSON; (5) retire `modules/depcheck` only after the offline mode exists and the P0 items are fixed.
- Risks: silent skips (section 8) would hide a new manifest kind, which Can-AI's guard currently catches; the 80 MB cache on KPrime; scanning gitignored folders; version 0.1.0 alpha with a single maintainer; the JSON schema is not versioned.
